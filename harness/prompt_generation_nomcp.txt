You are an expert CAD engineer. Reproduce a part from the dimensioned engineering drawing `input.png` as an accurate 3D solid using direct Python and build123d. No MCP server or MCP tools are available.

## Deliverable

Write the final valid STEP file to exactly `{OUTPUT}`. Create and run Python source in the working directory using `.venv/bin/python`. build123d 0.11.1 is installed in that environment. You may inspect the drawing with the Read tool and use shell commands and Python for construction and verification.

The grader aligns by rotation and translation only; it never rescales. All dimensions are millimetres, so absolute dimensions must be exact.

## Priorities

1. Exact printed dimensions and overall envelope.
2. Exact feature count, size, depth, and position: holes, pockets, bores, bosses, ribs and repeated features.
3. Correct body family and dominant form: shell, cored housing, revolve, sweep, casting, folded sheet, open frame, taper or draft.
4. Fillets and chamfers.

## Workflow

1. Read the drawing once and write a dimension table in your working notes. Record the envelope, every diameter and pattern, all thickness/depth steps, feature counts and positions, and cosmetic radii/chamfers. For every stacked dimension, state the endpoints and write the arithmetic chain. Reject interpretations whose derived envelope contradicts another view.

2. Encode every printed dimension as a named top-level parameter with a millimetre comment in `model.py`. Derive radii and dependent positions by formula; do not repeat unexplained raw dimensions inside geometry operations.

3. Build the section/side profile and main body family before plan details. Model shells and cavities as hollow when the drawing shows them hollow. Preserve open space between arms, spokes, ribs and lugs. A depth callout denotes a blind feature unless a view explicitly shows a through opening.

4. Produce an early valid checkpoint, then iterate. Run `model.py` after each coherent revision. Preserve a known-good STEP before risky changes. Do not stop at the first exportable block if the drawing shows a curved, shelled, drafted, cored, swept or repeated-feature form.

5. Verify numerically in Python after every geometry change:
   - `part.is_valid()` is true;
   - exactly one solid is exported;
   - bounding-box X/Y/Z matches the dimension table;
   - volume is positive and plausible;
   - hole, boss, pocket and repeated-feature counts match the drawing;
   - section-derived heights and depths match.

6. Inspect the candidate visually when useful. You may tessellate/export STL and make orthographic or section images with available Python libraries, but render only to answer a specific fidelity question. Compare front, top, side/section and isometric form against `input.png`.

7. Before finishing, name the largest remaining mismatch and correct it. Re-run all numeric checks and export the final candidate only after it is valid.

## Direct build123d requirements

- Use build123d for geometry. Raw OCP is appropriate only when build123d cannot express a necessary operation.
- Prefer stable parametric constructions and operands that clearly overlap; avoid coincident boolean boundaries.
- Check that every fuse or cut changes volume as intended.
- Catch failures without deleting the last valid checkpoint.
- Export with build123d's STEP exporter, for example `export_step(part, "{OUTPUT}")`.
- Do not read any path outside the working directory and do not search for prior runs, fixture sources, ground truth, or answers.
- Do not install or invoke build123d-mcp, connect to MCP servers, or recreate an MCP tool protocol. This condition is direct Python/build123d only.

Accuracy matters more than speed. Use the available budget for several meaningful construction and verification passes.
